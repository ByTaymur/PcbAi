## 3. Tekrar üretim

Önce tablodaki commit'lerde kaynakları `.pcbai-state/u0/repos/{jbom,bom_cpl,dfm,astra,esim,hbee,inspector}`
konumlarına getirin. eSim için çalışma ağacı gerekmez. Kaynak okuması dışında çalıştırma aşağıdaki gibi yapılır:

```powershell
.\.venv\Scripts\python.exe -m venv .pcbai-state/u0/env
.\.pcbai-state\u0\env\Scripts\python.exe -m pip install -r docs/spikes/U0-requirements.txt
$env:PCBAI_U0_PYTHON = (Resolve-Path .pcbai-state/u0/env/Scripts/python.exe).Path
.\.venv\Scripts\python.exe scripts/spike_u0.py --output .pcbai-state/u0/new-run
```

[U0-requirements.txt](U0-requirements.txt) deney ortamının gerçek pip freeze kaydıdır; PcbAi çalışma zamanı
bağımlılığı değildir. Script modülleri sabit source ağacından `-I -X utf8` ile başlatır; kaynak paketleri
çekirdeğe kurulmaz. Kurulum, clone ve ölçüm ham kayıtları `.pcbai-state/u0/` altında kalır.

KiCad programı mevcut yapılandırma/ortam/PATH keşfinden gelir; ölçülen sürüm 10.0.4, Python 3.11.5.
Ecc83 demosunun özel kopyası kullanıldı. Özel HOME/USERPROFILE/APPDATA ve KiCad config kopyası;
boş `.env`, secret/API_KEY ortam temizliği; shell=False, timeout ve Windows süreç ağacı sonlandırması.
Çıktı dizini yeni olmalıdır; önceki koşu üstüne yazılmaz. Kök dışı ve linked ancestor yollar reddedilir.

## 5. Kapı kararını etkileyen bulgular

### U0-F1 — ignored clearance gerçek ölçümü

Ecc83 özel kopyasında min_clearance=1 mm; bakır aynı, yalnız rule_severities.clearance değiştirilir.
Son tekrar aracında `pcb drc --severity-all` çıktısı error'da **69** clearance, ignore'da **0** clearance;
uygulayan ve bağımsız denetçi aynı sayıyı üretti. Önceki tek seferlik kopya deneyi 67 idi;
kabul fixture'ı için son scriptin girdileri ve 69 sayısı esas alınır.
Ignore koşusunun native `ignored_checks` listesinde clearance bulunur.
Mevcut PcbAi `check(scope=pcb)` iki koşuda da `checks_findings`; drc/parite/stats `ran`.
Ignore sebebiyle `checks_incomplete` üretmez. Her check boyunca proje revizyonu değişmedi.

Bu fixture başka bulgular taşıdığı için "ignore sonrası bütünüyle checks_ok" kanıtı değildir;
kanıt, 69 clearance'ın kaybolması ve zorunlu kapsam eksikliğinin raporlanmamasıdır.
Kaynak: `pcbai/kicad/cli.py`, `pcbai/tools/engine.py`; Astra `kicad/manufacturing.py:219–244`
ignored_checks ve kopyada rerun karşı örneğidir. **Sonraki ilk çekirdek işi R2-A1**:
ignored zorunlu kural → kapsam eksikliği/CLI exit 2; ERC ve DRC olumsuz fixture'ları.

### U0-F2 — pcb-dfm exit/score kapsam kabulü değildir

`pcb_dfm/cli/main.py`: run daima exit 0; gate summary eşikler. `--must-pass` CLI seçeneği yoktur.
`engine/run.py:368–400` not_applicable rank 0 ve bilinmeyen status için default 0 kullanır.
`engine/check_runner.py:265–285` uygulama eksikliği N/A, çökme fail üretir.
U3 adaptörü check_id kümesini, her gerekli status'u, ölçümü/provenansı ve şema sürümünü doğrulamalı;
eksik/bilinmeyen/N/A zorunlu kontrol incomplete olmalı. Toplam skor veya exit 0 kapı açamaz.

### U0-F3 — inspector PCB'siz heuristics temiz görünebilir

`rules/board_loader.py` PCB bulunmayınca None döndürür; heuristic kurallar bu durumda boş bulgu döndürür.
CLI'nin şematik-only analyze sonucu "executed/passed" olabilir. Bu davranış bağımsız koşuda tekrarlandı.
U5 adaptörü required PCB ve net/stackup girdilerini önce doğrulamalı; executed etiketi tek başına
kuralın gerçekten uygulanabildiği kanıt değildir. Bozuk PCB'nin ayrı başarısızlık sonucu korunmalı.

### U0-F4 — Hauksbee hedef/ADC/DMA kapsamı

`docs/cosim/MCU.md`: stok F103/F4 Renode platformlarında ADC enjeksiyonu yok/DROPPED.
`crates/hauksbee-mcu/db/mcu/stm32g4.soc.toml`: hedef G474; TIM sabit 16 MHz, clock tree yok,
ADC anlık/örnekleme zamanı yok, DMA transferi yok, FDCAN frame yok. F4 descriptor hedefi F407'dir.
G431CBU6 ve F429 aynı backend aile adı üzerinden doğrulanmış sayılamaz.
U7'de pin/AF statik denetimi ile periferik zamanlama/firmware simülasyonu ayrı kapsam olur.
